# GapForge v1.0.0

GapForge v1.0.0 is the stable, evidence-gated research ideation OS release. It turns broad research topics into auditable project state: literature campaigns, claims, evidence, novelty and prior-work gates, experiment workspaces, benchmark and replication packages, manuscript and artifact-evaluation packages, and release-gate reports.

v1 readiness passed. The external v0.9 pilot outcome was an accepted correct refusal, which is valid GapForge behavior: when the evidence does not support a defensible research direction, GapForge should refuse rather than invent one.

## Installation

Requires Python 3.11+.

```bash
git clone https://github.com/Ostailor/gapforge.git GapForge
cd GapForge
python -m venv .venv
source .venv/bin/activate
make install
```

Equivalent editable install:

```bash
python -m pip install -e ".[dev]"
```

## Quickstart

Run an offline-safe literature workflow:

```bash
export GAPFORGE_DISABLE_NETWORK=1
gapforge run "low false positive collusion detection" --v3 --max-papers 8 --build-index
gapforge report --strict
gapforge coverage
```

Run release-readiness checks:

```bash
gapforge compatibility-audit --v2 --write-report
gapforge artifact-hygiene --all --write-report
gapforge v1-readiness --write-report --json
```

## Major Features

- Literature campaigns with source coverage, search planning, canonicalization, prior-work recall, novelty dossiers, conservative stopping, and human review records.
- Codex/GPT-5.4 assisted workflows through task packs, direct runner integration, validated import, attestation, repair, rollback, and campaign review.
- Durable claim, evidence, counterevidence, gap, direction, review, run, project, campaign, workspace, benchmark, manuscript, and pilot state.
- Experiment execution with manifests, run records, result artifacts, parsed metrics, statistical checks, reproducibility checks, and failed/negative paths.
- Benchmark and replication packages with benchmark records, dataset consent/cache handling, comparison reports, low-FPR power checks, and replication manifests.
- Manuscript and artifact-evaluation packages with traceability, citations/BibTeX, venue checklists, anonymization checks, reviewer simulation, rebuttal plans, and submission package status.
- Correct refusal outcomes when source coverage, novelty evidence, prior-work review, or empirical support is insufficient.
- Release gates, compatibility audits, artifact hygiene checks, CLI/docs audits, versioned migrations, and backup snapshots.

## Pilot Outcome

The v0.9 external pilot for `low false-positive collusion detection in LLM multi-agent systems` was accepted as a correct refusal.

This is intentional. GapForge v1.0.0 does not force a research idea when evidence is weak. A correct refusal is a successful safety outcome when the literature coverage, novelty gate, prior-work review, or empirical support is not strong enough to recommend a direction.

## Limitations

- GapForge does not always produce a research idea.
- GapForge does not guarantee exhaustive autonomous literature review.
- GapForge does not guarantee novelty, correctness, empirical success, broad benchmark superiority, independent replication, publication readiness, venue submission, venue acceptance, or camera-ready readiness.
- Live sources can be unavailable, rate-limited, stale, incomplete, or fallback-heavy.
- PDF and full-text parsing can miss sections, references, tables, equations, and layout.
- Closest-prior-work and novelty gates reduce risk but cannot prove no relevant paper was missed.
- Fixture, smoke, deterministic fallback, and fake-agent paths validate workflow mechanics only; they are not real research-quality evidence.
- Optional model output remains untrusted until schema-valid, evidence-located, reviewed, and imported.
- Reviewer simulation is diagnostic and does not predict acceptance.
