# GapForge v0.9.0 Release Notes

GapForge v0.9 is the external pilot and v1-readiness upgrade. It adds a durable pilot runner, outcome classifier, idea gate, human review capture, v1 readiness gate, migration audit, CLI/docs audits, artifact hygiene audit v2, v9 release gate, and v9 offline eval fixtures.

The release validates that GapForge can run a real pilot honestly. It does not claim that the pilot produced a publication-ready research direction.

## Pilot Summary

- Pilot topic: `low false-positive collusion detection in LLM multi-agent systems`
- Pilot id: `pilot-low_fpr_collusion-20260507T234243Z`
- Outcome: **accepted correct refusal**
- Accepted direction: none
- Human review: accepted the refusal
- Product failures: none unresolved

The refusal is the accepted outcome because live source diagnostics reported degraded arXiv fallback metadata, required live-literature and novelty artifacts were incomplete, and the idea gate found no candidate research direction that should be promoted. GapForge did not force a generic idea into a research direction.

## v1 Readiness Status

- v1 readiness report generated: yes
- v1 readiness passed: no
- Blocking issue: migration/backward compatibility audit has not passed
- No unresolved pilot product failures: true
- v0.9.1 needed: not for a pilot product failure; v1 remains blocked until migration readiness is resolved. If that remediation is released before v1, it should be tracked as v0.9.1.

## Major Features

- External pilot spec and runner for the low-FPR collusion topic.
- Pilot outcome classifier for defensible direction, correct refusal, product failure, and incomplete outcomes.
- Real idea gate that accepts at most one primary direction and preserves rejected directions.
- External/human review capture with auditable reviewer metadata and acceptance state.
- v1 readiness gate across CI, historical release gates, pilot acceptance, audits, artifact hygiene, and human review.
- Schema migration and backward compatibility audit with backup-before-mutate migration behavior.
- CLI usability audit for command grouping, help text, deprecated aliases, and discoverability.
- Documentation usability audit for lifecycle docs, quickstarts, limitations, and overclaim/fake-evidence checks.
- Artifact hygiene audit v2 and gitignore verification.
- v9 release gate and v9 eval fixtures.

## Remaining Risks

- v1 readiness is blocked by migration/backward compatibility audit status.
- The real pilot refused before a defensible direction, manuscript draft, or real experiment result existed.
- Live-source availability can still prevent novelty assessment and should remain a refusal path.
- CLI/docs/artifact audits improve release safety but do not prove that all future workflows are ergonomic.
- Human review was captured from the operator, not from an independent domain expert.
