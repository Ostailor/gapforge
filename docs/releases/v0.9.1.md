# GapForge v0.9.1

Release type: migration compatibility remediation patch.

v0.9.0 passed the external pilot as an accepted correct refusal, but it was not v1-ready because the migration/backward compatibility audit failed. v0.9.1 fixes that blocker without adding product features or weakening the v1 readiness gate.

## What Changed

- Added historical migration fixtures for v0.1 through v0.9.
- Added a versioned migration registry and ordered migrators.
- Added backup snapshots before applied migration mutations.
- Added validation that protects claims, evidence, results, manuscript records, review records, blockers, and provenance.
- Added compatibility audit v2 for v1 readiness.
- Added migration blocker, fixture listing, migration-all, and migration reporting CLI paths.
- Updated v1 readiness to require compatibility audit v2 and to list next commands when blocked.
- Documented migration remediation, backup behavior, warnings, blockers, and recovery.

## v1 Status

GapForge is v1-ready after v0.9.1 remediation, but v1 is not tagged by this patch. The v1 release should be tagged separately after release-manager review.

## Warnings and Scope

`gapforge migrate-all --dry-run` can report warnings for ignored/generated local objects with ambiguous old versions. Those warnings do not block curated v1 readiness unless the object is curated release evidence.

v0.9.1 does not migrate raw PDFs, datasets, transcripts, prompt packs, caches, dashboards, task outputs, or unsafe generated bundles. Those artifacts remain generated/private unless separately restored or exported through a safe bundle.

## Recovery

Applied migrations write backups under `data/migrations/backups/` and records under `data/migrations/records/`. If a migration fails, inspect `gapforge migration-report`, restore from the relevant backup if needed, add an explicit version marker or migrator, and rerun:

```bash
gapforge migrate-all --dry-run
gapforge compatibility-audit --v2 --write-report
gapforge v1-readiness --write-report --json
```
