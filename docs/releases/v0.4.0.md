# GapForge v0.4.0 Release Notes

GapForge v0.4 is the campaign-level actual-run preparation release. It adds the state, task-pack, validated-import, handoff, repair, review, and release-gate machinery needed to run Codex/GPT-5.4 as a research agent. It is still not an exhaustive autonomous literature reviewer.

## What Changed

- Added first-class research campaigns with durable campaign state, steps, decisions, milestones, budgets, stop conditions, and reports.
- Added campaign controller modes: deterministic, fake-agent, Codex task-pack, Codex direct, and manual handoff.
- Added campaign-level Codex task packs for planning, literature scouting, deep reading, gap synthesis, novelty review, experiment architecture, reviewer panels, and stop decisions.
- Added direct runner and handoff workflows for Codex/GPT-5.4 actual runs.
- Added strict output validation, partial import, rollback snapshots, repair tasks, and import records.
- Added agentic literature expansion and novelty re-search loops where Codex proposes searches and GapForge validates/executes them.
- Added campaign reviewer/rebuttal loops and experiment code task generation.
- Added campaign-level human review and actual-run acceptance summaries.
- Added campaign dashboard pages for actual runs, canaries, agent tasks, imports, human reviews, and release-gate status.
- Added v4 campaign eval fixtures, metrics, API functions, and a machine-checkable v4 release gate.
- Added `make v4-smoke`, which runs the CI-safe fake-agent campaign canary and writes a release-gate report.

## How To Run v0.4

Deterministic campaign:

```bash
gapforge init-project "campaign project"
gapforge campaign-create "low false positive collusion detection" --project-id <project-id>
gapforge campaign-run --campaign-id <campaign-id> --mode deterministic --max-iterations 5
gapforge campaign-report --campaign-id <campaign-id>
```

Fake-agent smoke:

```bash
GAPFORGE_DISABLE_NETWORK=1 gapforge campaign-canary-run --profile fake_agent_campaign_regression
gapforge v4-release-gate --write-report
```

Codex task-pack/manual-handoff workflow:

```bash
export GAPFORGE_ENABLE_REAL_RUNS=1
export GAPFORGE_AGENT_MODE=task-pack
export GAPFORGE_AGENT_NAME=codex
export GAPFORGE_CODEX_MODEL=gpt-5.4

gapforge campaign-canary-plan --profile agentic_low_fpr_collusion
gapforge campaign-canary-run --profile agentic_low_fpr_collusion --real
gapforge campaign-task --campaign-id <campaign-id> --type novelty_reviewer
gapforge task-handoff --task-id <task-id>
# Run the task with Codex/GPT-5.4 externally, then:
gapforge campaign-validate-output --campaign-id <campaign-id> --task-id <task-id> --path <outputs>
gapforge campaign-import-output --campaign-id <campaign-id> --task-id <task-id> --path <outputs>
gapforge attest-agent-run --task-id <task-id> --agent codex --model gpt-5.4 --method task_pack --attester "<name>"
gapforge campaign-review --campaign-id <campaign-id> --accept --reviewer "<name>"
```

Direct runner workflow, when configured:

```bash
export GAPFORGE_ENABLE_REAL_RUNS=1
export GAPFORGE_AGENT_MODE=codex
export GAPFORGE_AGENT_NAME=codex
export GAPFORGE_CODEX_MODEL=gpt-5.4
export GAPFORGE_CODEX_COMMAND='<configured command template>'

gapforge codex-run --task-id <task-id> --direct
```

## Remaining Risks

- Direct Codex execution depends on a configured `GAPFORGE_CODEX_COMMAND`; without it, users must use task-pack/manual-handoff mode.
- Task-pack/manual-handoff actual-run acceptance depends on honest attestation, validated imports, and human review.
- Campaign output quality still depends on source coverage, available full text, and human review.
- v4 evals validate campaign behavior offline; they do not prove real research usefulness.

## Not Tested

- No direct Codex/GPT-5.4 runner was executed in this environment.
- No real Codex/GPT-5.4 campaign output was imported and accepted.
- No network-enabled real literature campaign was accepted.
- No manual-PDF actual Codex campaign was accepted.

## Migration From v0.3

Existing v0.3 project/run state remains compatible. v0.4 adds campaign-level objects and release-gate artifacts around existing projects. Users can continue deterministic v0.3-style workflows, then opt into campaigns with `campaign-create` and `campaign-run`.
