# GapForge v0.4.1 Release Notes

GapForge v0.4.1 is a Codex workflow usability patch for the v0.4 campaign system. It keeps deterministic and fake-agent CI paths intact while making real Codex/GPT-5.4 task-pack and direct-run workflows practical to diagnose, execute, validate, import, attest, and review.

GapForge is still not an exhaustive autonomous literature reviewer. The accepted real canaries validate the workflow path, not broad literature quality.

## What Changed

- Added `gapforge setup-codex` for direct/task-pack/manual-handoff/fake mode setup status.
- Added `gapforge codex-doctor` for task-pack, output, validation, import, attestation, review, and actual-run blocker diagnosis.
- Added copy-paste Codex handoff v2 files: `README_FIRST.md`, `CODEX_PROMPT.md`, `OUTPUT_CONTRACT.md`, `VALIDATE_AND_IMPORT.sh`, minimal JSON skeletons, and output examples.
- Added direct Codex command preview and dry-run support.
- Added a local `codex exec` wrapper for direct runner mode when real runs are enabled and the Codex CLI is available.
- Made output-file validation less brittle through required/optional/one-of contracts while keeping evidence, citation, locator, and novelty gates strict.
- Added `validate-import-all`, task output discovery, latest campaign task lookup, and clearer repair commands.
- Added valid and invalid Codex output examples.
- Improved actual-run attestation status and release-gate blocker messaging.
- Added minimal single-task Codex handoff canaries and manual-PDF/full-text Codex reading canaries.
- Rewrote Codex usage docs and added `docs/CODEX_QUICKSTART.md`.

## How To Run

Deterministic checks:

```bash
make ci
make eval
gapforge eval --v2 --write-report
gapforge eval --v3 --write-report
gapforge eval --v4 --write-report
make v2-smoke
make v3-smoke
make v4-smoke
```

Diagnose Codex setup:

```bash
gapforge setup-codex
gapforge setup-codex --json
```

Minimal task-pack workflow:

```bash
GAPFORGE_ENABLE_REAL_RUNS=1 gapforge campaign-canary-run --profile single_task_codex_handoff --real
gapforge codex-handoff --task-id <task-id> --print-prompt
# Run Codex/GPT-5.4 and write JSON outputs to outputs/.
gapforge validate-import-all --task-id <task-id>
gapforge attest-agent-run --task-id <task-id> --agent codex --model gpt-5.4 --method task_pack --attester "<name>"
gapforge campaign-review --campaign-id <campaign-id> --accept --reviewer "<name>"
gapforge campaign-canary-complete --canary-id <canary-id>
```

Direct runner workflow:

```bash
export GAPFORGE_ENABLE_REAL_RUNS=1
export GAPFORGE_AGENT_MODE=direct
export GAPFORGE_AGENT_NAME=codex
export GAPFORGE_CODEX_MODEL=gpt-5.4
gapforge codex-command-preview --task-id <task-id>
gapforge codex-run --task-id <task-id> --direct --dry-run
gapforge codex-run --task-id <task-id> --direct --require-direct
```

## Remaining Risks

- The accepted real canaries are small workflow canaries. They prove the actual-run mechanics, not exhaustive literature-review quality.
- Broad, multi-step real research campaigns over live literature remain future validation work.
- Task-pack/manual-handoff acceptance depends on honest human attestation that Codex/GPT-5.4 produced the outputs.
- Direct runner behavior depends on the local `codex` CLI and its configured authentication.
- Generated campaign outputs, transcripts, PDFs, dashboards, and caches remain ignored and should not be committed unless intentionally curated as tiny fixtures.

## Not Tested

- Large real-world campaign quality over multiple live source searches.
- Direct runner behavior on machines without the local Codex CLI.
- Paid/provider LLM adapters outside the Codex CLI path.
