# GapForge v0.3.0 Release Notes

GapForge v0.3.0 is the semantic project-memory and LLM-assisted research upgrade. It extends the v0.2 full-text evidence system with multi-run project memory, hybrid retrieval, optional provider/AgentClient model paths, direction maturation, related-work matrices, experiment protocols, manuscript package exports, dashboards, review queues, and release canary gates.

GapForge v0.3.0 is still not an exhaustive autonomous literature reviewer. It is a conservative, evidence-located research ideation system. Deterministic and offline-safe paths remain the default, and live model/API use is opt-in.

## What Changed

### Project Memory

- Added project-level memory for topics, corpus papers, memory records, rejected ideas, human decisions, and research directions.
- Added `gapforge init-project`, project attachment, project status/report commands, and project memory sync.
- Added cross-run corpus deduplication and cumulative rejected-idea/human-decision tracking.

### Hybrid Retrieval Index

- Added a reusable hybrid lexical/local-semantic retrieval index over paper metadata, sections, evidence spans, notes, claims, gaps, novelty dossiers, and project memory.
- Added deterministic local hash embeddings and fake embedding paths for offline tests.
- Added `gapforge build-index`, `search-index`, and `explain-retrieval`.

### Optional LLM and Codex/GPT-5.4 Assistance

- Added an optional provider LLM adapter with JSON guards, budget tracking, transcript logging, secret redaction, and graceful provider-unavailable failures.
- Added optional LLM-backed deep-reading, gap-mining, novelty-dossier, and reviewer workflows while preserving deterministic defaults.
- Added `AgentClient` separately from `LLMClient` for Codex/GPT-5.4 task-pack and actual-run workflows.
- Added Codex-compatible task packs, strict schema validation, validated patch import, fake-agent CI mode, canary profiles, and human review harness.

### Full-Text Structure

- Added v0.3 extraction hooks for references, tables, equations, captions, and OCR-status records.
- Citation graph construction can use parsed reference records when available.
- OCR remains optional and is not required for default tests.

### Source Coverage and Active Research Loop

- Added source policy profiles and literature coverage stopping assessments.
- Added active-loop decisions, research budgets, and stop conditions for deciding when to search more, parse more, read more, expand citations, check novelty, request human review, or stop.
- Added `gapforge run --v3 --active` and active-loop inspection commands.

### Claim Safety and Direction Maturation

- Added a project claim graph with duplicate and contradiction detection.
- Added research direction maturation gates from `seed` through `manuscript_ready` or `rejected`.
- Added review queues for unsupported high-impact claims, unknown novelty, contradictions, source-policy waiver requests, and near-ready directions.

### Related Work, Experiments, and Manuscripts

- Added related-work matrices by direction with relationship taxonomy, must-read papers, baseline candidates, and reviewer omission risk.
- Added experiment protocols, baseline candidate extraction, reproducibility checklists, and statistics guidance.
- Added paper package exports with manuscript outlines, related-work matrix, experiment protocol, limitations, reviewer objections, rebuttal plan, bibliography, claim ledger, and evidence index.
- Export rules explicitly prohibit fake results and label expected results as hypothetical.

### Dashboard, API, and Artifact Safety

- Added static HTML dashboards for project/run inspection without a server.
- Added a lightweight Python API layer for notebooks, scripts, and future UI surfaces.
- Added artifact safety auditing, generated-artifact cleanup, safe-bundle export, and redaction for model transcripts/secrets.

### Evaluation and Documentation

- Added v0.3 curated fixture structure and metrics for retrieval relevance, prior-work recall proxy, related-work matrix quality, direction maturity, protocol completeness, manuscript honesty, contradiction detection, source-policy compliance, and LLM output grounding.
- Updated README, architecture, skills, source, eval, testing, limitations, release, and Codex-readable skill docs for v0.3.
- Added real-run acceptance, canary, Codex research-agent, and human review checklist docs.

## How To Run v3

Offline deterministic v0.3 smoke:

```bash
export GAPFORGE_DISABLE_NETWORK=1
gapforge run "low false positive collusion detection" --v3 --max-papers 8 --build-index
gapforge report --strict
gapforge coverage
```

Project-level v0.3 smoke:

```bash
make v3-smoke
```

Project memory workflow:

```bash
gapforge init-project "monitoring collusion research"
gapforge run "low false positive collusion detection" --v3 --project-id monitoring-collusion-research --max-papers 20 --build-index
gapforge sync-project-memory --project-id monitoring-collusion-research
gapforge project-report --project-id monitoring-collusion-research
gapforge dashboard --project-id monitoring-collusion-research
```

Active loop:

```bash
GAPFORGE_DISABLE_NETWORK=1 gapforge run "low false positive collusion detection" --v3 --active --budget small --source-profile ai_safety
gapforge active-decisions --run-id <run-id>
```

## Deterministic and Offline Mode

Deterministic mode is the default. It requires no live LLM, no embedding API, and can run with `GAPFORGE_DISABLE_NETWORK=1`.

Offline outputs are smoke-test artifacts. They should show fallback/source-coverage warnings and must not be presented as real literature conclusions.

## Optional LLM Mode

Prompt-pack mode writes tasks for manual Codex/GPT-5.4 workflows without live calls:

```bash
gapforge run "topic" --v3 --mode prompt-pack --agent codex --llm-novelty --build-index
```

Fake-agent mode validates schema/task-pack plumbing in CI-safe offline runs:

```bash
GAPFORGE_DISABLE_NETWORK=1 gapforge run "topic" --v3 --mode fake-agent --agent fake --llm-gaps
```

Actual Codex/GPT-5.4 mode is opt-in:

```bash
export GAPFORGE_ENABLE_REAL_RUNS=1
export GAPFORGE_AGENT_MODE=codex
export GAPFORGE_AGENT_NAME=codex
export GAPFORGE_CODEX_MODEL=gpt-5.4
gapforge run "topic" --v3 --mode llm-assisted --agent codex --require-real-agent
```

Provider LLM mode is also opt-in. Invalid JSON, unsupported evidence locators, unknown prior-work IDs, and unsupported high-confidence claims are rejected before state mutation.

## Migration Notes From v0.2

- v0.2 run directories still load; v0.3 adds project-level state without removing run-local state.
- Existing `gapforge run --v2` workflows remain available.
- v0.3 project memory is opt-in through `init-project`, `--project-id`, or attach/sync commands.
- v0.3 retrieval indexes are generated artifacts and can be rebuilt.
- v0.3 LLM/AgentClient features are disabled by default and do not affect deterministic v0.2 behavior.
- Reports now label v3 runs as `Report version: v0.3`; v2 reports continue to use `v0.2`.

## Remaining Risks

- v0.3 remains an ideation and evidence-management system, not an exhaustive reviewer.
- Hybrid retrieval improves recall pathways but does not prove novelty.
- Optional model outputs remain untrusted until schema-valid, evidence-located, and imported through validation.
- Full-text structure extraction is heuristic; tables/references/equations may be incomplete.
- Source policy profiles are conservative heuristics and require field-specific review.
- Manuscript packages are starter kits and must not contain fake results.
- Real Codex/GPT-5.4 acceptance was not completed for this release pass.

## Not Tested

- No live Codex/GPT-5.4 actual-run canary was accepted.
- No live provider LLM call was required or validated in CI.
- No live source/network literature run is claimed as part of this release.
- OCR provider integration is hook-only and not tested with a real OCR backend.
- No manuscript package was validated as submission-ready by a domain expert.
