# GapForge v0.6.0 Release Notes

GapForge v0.6 is the experiment execution and empirical validation upgrade. It moves from experiment-ready research directions to durable experiment workspaces with run manifests, execution logs, result artifacts, statistical analysis, reproducibility checks, empirical reviewer simulation, and paper packages that distinguish planned work from executed results.

GapForge still must not fabricate experimental results. A protocol, scaffold, or smoke run is not evidence of empirical success.

## What Changed

- Added first-class experiment workspaces, run manifests, execution records, and hashed result artifacts.
- Added dataset registry, dataset cards, loaders, and validation.
- Added baseline registry, baseline cards, and related-work-driven baseline selection.
- Added metric registry, statistical test planning, confidence-interval helpers, and low-FPR sample-size warnings.
- Added experiment code scaffold v2 with runnable workspace code, tests, configs, and smoke scripts.
- Added constrained Codex/GPT-5.4 experiment-code tasks for implementing datasets, baselines, metrics, runners, ablations, tests, smoke debugging, and result analysis.
- Added experiment runner support with stdout/stderr capture, timeout handling, expected-output checks, result hashing, and failure preservation.
- Added result parsing, metric results, empirical claims, result summaries, and claim-ledger integration.
- Added statistical analysis reports, reproducibility checks, empirical reviewer simulation, and paper package v2.
- Added v6 release gate, v6 eval fixtures/metrics, experiment dashboard pages, APIs, docs, and Codex-readable skills.

## How to Run v0.6

```bash
gapforge experiment-workspace-create --project-id <project-id> --direction-id <direction-id>
gapforge dataset-register --workspace-id <workspace-id> --name "fixture examples" --path data/fixture.csv --dataset-type fixture --license MIT
gapforge baseline-register --workspace-id <workspace-id> --name "heuristic baseline" --baseline-type heuristic --implementation-path code/src/baselines.py
gapforge metric-register --workspace-id <workspace-id> --name "false positive rate"
gapforge scaffold-experiment-code --workspace-id <workspace-id>
gapforge experiment-manifest-create --workspace-id <workspace-id> --run-type smoke --command "python code/src/run_experiment.py" --expected-output results/smoke_metrics.json --random-seed 123
gapforge experiment-run --workspace-id <workspace-id> --manifest-id <manifest-id>
gapforge parse-results --execution-id <execution-id>
gapforge analyze-results --execution-id <execution-id>
gapforge reproducibility-check --execution-id <execution-id>
gapforge empirical-review --execution-id <execution-id>
gapforge export-paper-package-v2 --workspace-id <workspace-id>
gapforge v6-release-gate --write-report --json
```

## Remaining Risks

- Fixture smoke execution validates plumbing and artifact discipline, not empirical performance on real datasets.
- Codex experiment-code tasks can produce useful code, but outputs remain untrusted until validated and imported.
- Low-FPR experiments can still be underpowered without sufficient samples.
- Reproducibility checks are structural; they do not guarantee independent replication.
- v5 literature quality and novelty gates remain prerequisites for serious empirical claims.

## Not Tested

- Expensive real-world main experiments.
- External benchmark dataset downloads at scale.
- Multi-machine or GPU execution environments.
- Independent replication by another researcher.
- Statistical significance claims beyond fixture-level analysis.
